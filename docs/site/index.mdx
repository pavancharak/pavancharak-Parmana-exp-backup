## What Parmana is

Parmana establishes a verifiable trust chain between business authorization, policy
evaluation, runtime execution, and execution evidence. It lets an organization verify
**what** an automated system executed — not simply trust that it executed correctly.

This is not a single claim. It's a set of specific, separately-provable guarantees, each
tagged below by how far it actually is from "built and tested" today. Source:
[`docs/CLAIMS.md`](https://github.com/parmana-ai/parmana/blob/main/docs/CLAIMS.md), the
authoritative claims register this site mirrors.

## The trust chain, at a glance

```
Business Transaction → Policy Evaluation → Decision → Signed Execution Authorization
        │                                                        │
        ▼                                                        ▼
 Execution Trust Record ◄──────────────────────────────  Execution Gateway
        │                                              (content-binding check)
        ▼                                                        │
   Verification                                                  ▼
   (integrity, signature,                                   Connector
    authorization binding)                              (reference: HTTP)
```

<Warning>
**The gateway stage is real but not wired into the default server.** The plain,
running API server (`packages/api`) never constructs an `ExecutionGateway` — its
`application` singleton is built with no `executionSystem` argument
(`packages/api/src/application.ts`). So `POST /execute` against a stock local server
does **not** get content-binding enforcement today. See
[Content Binding & TOCTOU](/concepts/content-binding-toctou) for the full trace and what
wiring the gateway in requires.
</Warning>
